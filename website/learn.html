What is an agentic framework?

A large language model (LLM) like GPT-4o is great at producing text, but on its own it can't do anything — it can't look up your data, call an API, or remember what you said five minutes ago. An agent wraps an LLM so it can.

An agentic framework is a toolkit for building these agents: it handles talking to the model, letting the agent call your code (“tools”), remembering the conversation (“memory”), and coordinating several agents that each do one job well. MOYA is one such framework, written in Python and kept deliberately small so you can read it.

Mental model: an agent ≈ an LLM + instructions + (optional) tools + (optional) memory. The framework is the glue that wires those together and runs them.

What is an agent?

In MOYA, you make an agent with one function call. You pick a provider, give it a name and a short description of its job, and optionally a system prompt that shapes how it behaves.

agent.py
from moya import create_agent

agent = create_agent(
    "openai",                       # provider: openai, ollama, bedrock, azure
    name="assistant",
    description="A friendly helper",
    system_prompt="You are concise and kind.",
)

print(agent.handle_message("Hi! Who are you?"))

That's a complete, working agent. handle_message sends your text to the model and returns its reply. Change "openai" to "ollama" and the same code runs against a model on your own laptop.

Tools — let the agent use your code

A tool is simply a Python function the agent is allowed to call. You write a normal function with a docstring; MOYA reads its name, arguments and description and offers it to the model. When the model decides it needs that function, MOYA runs it and feeds the result back.

tools.py
from moya import create_agent, ToolRegistry, Tool

def get_weather(city: str) -> str:
    "Return the current weather for a city."
    return "Sunny, 24C"

tools = ToolRegistry()
tools.register_tool(Tool(name="get_weather", function=get_weather))

agent = create_agent("openai", name="assistant",
                     description="Knows the weather",
                     tool_registry=tools)

print(agent.handle_message("What's the weather in Kyoto?"))

Ask about the weather and the agent will call get_weather for you. In real life this function might hit a weather API or query a database — the agent doesn't care, it just calls the function.

Memory — so the agent remembers

By default each message is independent. Memory lets an agent recall earlier turns. MOYA gives you two kinds you can use alone or together:

  • Short-term — keeps the last N messages as working context. Fast and in-memory.
  • Long-term — writes the whole history to disk and can recall the most relevant past messages later. Survives restarts.
memory.py
from moya import create_agent
from moya.memory import (
    ShortTermMemory, LongTermMemory, CompositeMemory)

memory = CompositeMemory([
    LongTermMemory(base_path="./memory"),   # persistent
    ShortTermMemory(window_size=10),        # recent context
])

agent = create_agent("openai", name="assistant",
                     description="Remembers you", memory=memory)
Good to know: memory is organised by thread — one conversation. Pass the same thread_id across turns and the agent treats them as one chat.

Multiple agents working together

Complex jobs are easier when each agent does one thing well. MOYA gives you a few ways to combine them:

  • Orchestrators route an incoming message to the right agent.
  • Delegation lets a coordinator hand tasks to specialists — sequentially or in parallel — and combine their answers.
  • Pipelines chain agents into steps, with support for parallel branches, loops and conditional routing.
pipeline.py
from moya import Pipeline, AgentStep

# researcher gathers facts, writer makes them readable
pipeline = Pipeline([
    AgentStep(researcher),
    AgentStep(writer),
])

answer = pipeline.run(thread_id="t1",
                     message="Explain black holes simply")

Build your first agent, step by step

Let's assemble the pieces. Each step is a small change on the previous one.

Step 1 — a plain agent

step1.py
from moya import create_agent

agent = create_agent("openai", name="tutor",
                     description="Explains ideas simply")
print(agent.handle_message("What is a qubit?"))

Step 2 — give it a tool

step2.py
from moya import create_agent, ToolRegistry, Tool

def search_notes(topic: str) -> str:
    "Look up short notes on a topic."
    notes = {"qubit": "A qubit can be 0, 1, or both at once."}
    return notes.get(topic.lower(), "No notes found.")

tools = ToolRegistry()
tools.register_tool(Tool(name="search_notes", function=search_notes))

agent = create_agent("openai", name="tutor",
                     description="Explains ideas simply",
                     tool_registry=tools)
print(agent.handle_message("Use your notes: what is a qubit?"))

Step 3 — add memory

step3.py
from moya.memory import ShortTermMemory

agent = create_agent("openai", name="tutor",
                     description="Explains ideas simply",
                     tool_registry=tools,
                     memory=ShortTermMemory(window_size=8))

agent.handle_message("My name is Ada.",           thread_id="t1")
print(agent.handle_message("What's my name?",     thread_id="t1"))

Because both calls share thread_id="t1", the second one remembers the first.

Step 4 — a second agent in a pipeline

step4.py
from moya import Pipeline, AgentStep

writer = create_agent("openai", name="writer",
                     description="Rewrites text to be clear and short")

pipeline = Pipeline([AgentStep(agent), AgentStep(writer)])
print(pipeline.run(thread_id="t1", message="Explain a qubit"))
You just built a two-agent system with a tool and memory. The full, runnable versions live in examples/research_assistant and examples/support_desk.
